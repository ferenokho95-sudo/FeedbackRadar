# FeedbackRadar

Анализ отзывов и поиск проблем продукта. Работающий локальный проект для портфолио: Python, HTTP API, браузерный интерфейс, тесты и готовый пример отчёта.

## Быстрый запуск на Windows

1. Полностью распакуйте ZIP в отдельную папку. Не запускайте файлы внутри архива.
2. Установите Python **3.11 или 3.12** с python.org (с Python Launcher `py`).
3. Дважды нажмите **START_WINDOWS.bat** и дождитесь строки с адресом сервера.
4. Откройте **http://127.0.0.1:8011** в браузере. Окно консоли оставьте открытым.
5. Для остановки нажмите Ctrl+C в консоли.

При первом запуске создаётся `.venv` и устанавливаются зависимости. Для установки scikit-learn требуется интернет. Сам Python в ZIP не включён. Если окно сообщает об ошибке, оставьте его открытым и прочитайте сообщение. Если порт занят, запустите `python app.py serve --port 8111` из терминала и откройте указанный адрес.

## Запуск из терминала (Windows / macOS / Linux)

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app.py serve
# macOS / Linux вместо этого:
# .venv/bin/python -m pip install -r requirements.txt
# .venv/bin/python app.py serve
```

Все дальнейшие команды `python` выполняйте интерпретатором созданного окружения.

## Что реализовано

- Загрузка CSV из браузера, проверка схемы, дат, оценок и уникальности ID.
- Классификация 4 тем: оплата, доставка, интерфейс, поддержка; TF-IDF + LogisticRegression.
- Низкая уверенность → ручная проверка; исправления сохраняются в SQLite и привязаны к хешу текста.
- Удаление точных текстовых дублей, выделение жалоб по оценке ≤3.
- Подтемы жалоб, примеры и прозрачный скоринг приоритетов.
- Holdout-отчёт с precision, recall, F1, confusion matrix, coverage и accepted accuracy.
- Экспорт JSON, отчёт для бэклога и локальный дашборд.

## Демонстрация за 2–3 минуты

1. Откройте дашборд: комплектный CSV загрузится автоматически.
2. Посмотрите темы и кандидатов в бэклог, раскройте примеры отзывов.
3. Выберите тему вручную у одного отзыва: исправление сохранится.
4. Загрузите `data/reviews.csv` кнопкой загрузки и скачайте JSON.
5. Откройте `reports/example/REPORT.md` и `evaluation.json`.
6. Для проверки собственного файла: `python app.py demo --csv my_reviews.csv --out reports/my_run`.

## Готовые результаты и повторный запуск

В `reports/example/` уже есть JSON и `REPORT.md` с результатами выполненного локального прогона. Данные синтетические, результаты не выданы за работу с клиентами.

```bash
python app.py demo
python -m unittest discover -s tests -v
```

`demo` пересоздаёт файлы в `reports/example/`. Пользовательские данные интерфейса остаются в `storage/app.sqlite3`. Чтобы начать с нуля, остановите сервер, при необходимости сделайте резервную копию и удалите только папку `storage/`.

## Структура

- `app.py` — CLI и HTTP-маршруты.
- `core.py` — предметная логика и работа с результатами.
- `common.py` — сервер, SQLite, поиск и клиент API (используются нужные проекту части).
- `web/` — HTML, CSS, JavaScript без CDN и сборщика.
- `data/` — исходные демонстрационные данные.
- `tests/` — автоматические проверки.
- `docs/` — описание продукта, API и сценарий дальнейшего тестирования.
- `.github/workflows/tests.yml` — конфигурация CI для Python 3.11/3.12.

## Ограничения

Разметка — одна основная тема на отзыв; несколько тем в одном сообщении не поддерживаются. Синтетический train (64 текста) и holdout (28 текстов) маленькие и близки к демонстрационному домену. Не переносите эти метрики на реальные отзывы. Порог .45 фиксирован; вероятности не калиброваны. Оценка ≤3 — явное правило определения жалобы, а не обученная тональность. Подтемы определяются словарём. Score учитывает частоту и фиксированную severity, не выручку и не эффект улучшения. Исправления не переобучают модель. Дубликаты определяются по нормализованному тексту; одинаковые тексты разных пользователей будут объединены.

Приложение слушает только `127.0.0.1`, рассчитано на одного локального пользователя и не предназначено для публичного размещения без доработки сервера, авторизации и обработки нагрузки. Секреты не включены. Windows BAT и реальные внешние LLM отдельно не запускались; подробности фактических проверок — `docs/VERIFICATION.md`.
